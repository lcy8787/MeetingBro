# 報告功能進度

已加入純文字報告 schema、版本化 SQLite migration、報告 revision 儲存及讀取 API。錄音時的 rolling／cumulative／final 摘要會轉成可查閱來源的即時報告；會議歷史可按需要生成報告。本機 Ollama 可用時會以分段 JSON 生成報告，否則顯示逐字稿原文；引用片段會檢查是否屬於同一會議，並檢查數字是否出現在引用文字中；格式不合或引用不合法時最多修復一次，仍失敗便退回原文。這些檢查不能證明語義正確，仍須人工核對。

已有 React 報告檢視、章節展開及導航、複製、簡報模式，以及獨立 `meeting-report.html` 匯出。HTML 把不可信文字轉義，使用內嵌受控樣式及腳本，不依賴後端或外部資源。複製功能在簡報模式下亦包含隱藏章節，並在 Clipboard API 不可用時嘗試後備複製；目前只用模擬 DOM 測試，不能代替真實瀏覽器測試。尚未在 Safari、Chrome 或手機實機驗收；圖表、內容導向排版、三類會議的完整驗收及瀏覽器實機重連驗收仍未完成。短暫連線中斷後可透過會話快照恢復報告，但後端程序重啟不支援續錄。

最終摘要已改用 SQLite 持久佇列，狀態為 queued、running、succeeded 或 failed；後端重啟時會重新排隊中斷的工作，歷史會議可重試失敗工作。摘要快照與成功狀態在同一事務寫入；停止前 ASR 超時會保存失敗狀態，提示逐字稿可能不完整；使用者應先檢查再考慮重試。程序終止或模型語義錯誤仍不能視為已驗收。其他限制見 phase-2-3-progress.zh-HK.md。
