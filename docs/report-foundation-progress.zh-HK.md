# 報告內容編排與渲染

目前沿用 `generate_report()` → `ReportDocument` → React／獨立 HTML 的流程，保留報告 revision、來源查看、選項切換、待辦勾選、章節收合／導航及複製。

## 語義編排

`reports/components.py` 集中定義模型可用的元件、資料格式和編輯 Prompt。模型在同一次生成請求中先理解主題、子題、觀點、例子、結論、比較、因果、時間、數據及講者立場，再輸出標題、簡短總覽和主題章節。一般說明使用文章段落；比較、表格、流程、時間線、優缺點、數值及重點各用相應元件。資料不足時使用文字，不強制加入圖表或互動。

長逐字稿維持原有分段預算和每段一次模型請求，後段收到有大小上限的已涵蓋內容、講者及主題綱要，延續主題 ID，避免以逐字稿分段直接建立 Part。相同主題 ID 或標題會合併；經來源及講者核對後的相同區塊會移除重複並合併引用。不同立場、後來修正和未能確認講者相同的內容不會單憑相似文字合併。語義改寫的去重依賴模型遵守 Prompt；這不是語義等價的形式驗證。

總覽不再複製正文前幾個區塊。渲染器採用文章層級、留白和分隔線，普通段落不加卡片；需要並排的內容依可用寬度呈現 1–3 欄，表格可橫向捲動，次要詳情與來源可收合。模型只供應 JSON 純文字，不供應 HTML 或腳本。

## 標題同步

成功生成的具體主題標題保存於報告 revision。會議列表從最新已儲存的 `meeting` 類型 LLM 報告讀取標題，取代原來的逐字稿首句；未有報告時保留原本預覽。產生摘要成功會重新整理左側抽屜，錄音中的項目亦使用新標題。重開程式後標題仍可由已儲存報告恢復；失敗生成不會覆寫既有標題。無需另加標題資料欄位或模型請求。

## 相容與來源驗證

保留 OpenAI-compatible client 和現有 API。新回應使用章節 JSON，亦接受舊版 flat `blocks`；舊報告缺少的新欄位使用預設值。表格使用 `columns` 和帶獨立 `source_segment_ids` 的 `rows`。總覽、章節／報告標題、正文、選項及表格每列會核對來源與數字；SQLite 在手動儲存及最終摘要提交時再次檢查所有引用是否屬於該會議。不合法回應直接失敗，不額外付費要求模型修復。

這些檢查不能證明每句話的語義或講者歸屬正確，亦不會把單純出現在來源中的數字視為統計關係的證明。

## 驗證

新增測試涵蓋語義章節、總覽不複製正文、跨段主題延續及去重、講者區分、表格格式與逐列來源、中文數字、來源越界、HTML 轉義、完整複製，以及標題更新／重開後保留／生成失敗保留舊標題。瀏覽器以合成資料驗證桌面與 390px 窄版、選項切換、待辦勾選，以及按「產生摘要」後的抽屜標題更新；未以真實付費模型輸出作端到端品質驗收。
